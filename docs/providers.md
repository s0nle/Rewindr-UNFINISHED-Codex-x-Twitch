# Provider integration record

Documentation checked on October 27, 2026 before implementing the integration. Installed versions are pinned in `package.json` and `package-lock.json`.

- TwelveLabs Node SDK: **`twelvelabs-js@1.3.6`**, verified through the npm registry and the installed published SDK types/source. The adapter uses the exported `TwelvelabsApiClient`; this lower-level client exposes the documented asset/indexed-asset operations and allows SDK serialization to stay in one place. Authentication uses `x-api-key`, managed by the SDK. Default environment: `https://api.twelvelabs.io/v1.3`.
- Model: **`marengo3.0`**, with index options `visual` and `audio`; searches use `visual`. Existing indexes are checked for the same configuration. [Index SDK documentation](https://docs.twelvelabs.io/sdk-reference/node-js/manage-indexes), [model requirements](https://docs.twelvelabs.io/docs/concepts/models/marengo/marengo-3-0).
- Current model requirements list 4 seconds–4 hours, file size ≤4 GB, resolution 360×360–5184×2160, and aspect ratio within 2.4:1 in either orientation. This prototype narrows duration to 20–30 minutes and input encoding to browser-playable MP4. Older release notes mention 6 GB; the implementation uses the smaller limit from the current model requirements.
- Use [multipart asset uploads](https://docs.twelvelabs.io/sdk-reference/node-js/upload-files/multipart-uploads), not the legacy task that combines uploading and indexing. Asset multipart transport accepts videos up to 10 GB, but model limits still apply. Direct local asset uploads are limited to 200 MB, so they are not used for broadcast files. Transport parts remain one video, with original timestamps.
- The adapter calls session creation, requests fresh presigned URLs, streams one source byte range per PUT, records its ETag, and reports completion. SDK creation responses expose `uploadId`, `assetId`, `chunkSize`, `totalChunks`, and optional `uploadHeaders`. Wire JSON uses snake_case. No API key is sent to presigned storage URLs. Non-idempotent create calls disable SDK retries; part PUT/report operations support retries and checkpoints.
- [Asset retrieval](https://docs.twelvelabs.io/sdk-reference/node-js/manage-assets) returns processing/ready/failed. After ready, [indexed asset creation](https://docs.twelvelabs.io/sdk-reference/node-js/index-content) returns an indexed asset ID; retrieval reports pending/queued/indexing/ready/failed. Optional SDK fields are validated at the adapter boundary before use.
- [Search response schema](https://docs.twelvelabs.io/sdk-reference/node-js/search): `start`, `end`, `videoId`, and `rank` are used for clip results. The adapter requests `groupBy: clip`, uses [the documented ID filter](https://docs.twelvelabs.io/docs/guides/search/filtering), validates source IDs and time ranges, and sorts by ascending provider rank. Marengo 3.0 does not supply calibrated confidence scores. The current [release notes](https://docs.twelvelabs.io/docs/get-started/release-notes) distinguish Marengo 3.5 embeddings from Marengo 3.0 managed search; no model upgrade was substituted.
- Reference-image search was added after checking the current search SDK documentation again: `queryMediaType: image` and `queryMediaFile` use a temporary local PNG/JPEG, optionally with `queryText` for a composed query. Temporary reference files are deleted after the request. This is a managed search query, not a new indexed asset or entity enrollment. [Query engineering guidance](https://docs.twelvelabs.io/docs/guides/search/query-engineering) recommends descriptive visual phrasing, but live diagnosis of this case showed that rephrasing alone did not reliably remove distractors.
- Query size: provider limit 500 tokens. The application also limits input to 1,000 characters, without pretending character counts enforce a token budget. Oversized/rejected provider queries are surfaced as search failures.

Local stack: Fastify **5.12.7**, multipart **10.1.6**, React **19.3.1**, Vite **8.3.5**. The build uses [Vite's official guide](https://vite.dev/guide/) and [React's client root API](https://react.dev/reference/react-dom/client/createRoot). Media tools are packaged by ffprobe-static and ffmpeg-static; [FFmpeg documentation](https://ffmpeg.org/documentation.html) is the reference for media operations. Direct FFmpeg manual fetches timed out during implementation.

Live diagnosis: the account accepted Marengo index creation but returned HTTP 422 `asset_storage_limit_exceeded` for a 3,698,141,561-byte upload request against a 3,221,225,472-byte storage allowance. This was reproduced with a session request containing only filename and size; no media transfer occurred. Successful media upload, indexing, and actual retrieval responses remain outstanding.

No other provider integration was started. Supabase, Mux, Twitch, OpenAI, and Railway documentation must be checked immediately before implementing their respective stages.
